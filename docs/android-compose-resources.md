# Compose locale resources in Android applications

Compose 1.10.3 supplies generated resources through Android variant assets. The shared Compose
convention previously enabled an Android library without enabling Android resources. Kotlin
resource accessors compiled, but the generated English and Indonesian CVR files were missing
from the accepted dev, staging and production APKs. Mobile found this during actual release
startup, where reading a localized loading label threw MissingResourceException.

The convention now applies the existing `starter.android.resources` plugin. This enables the
normal Android asset pipeline for Compose modules; no resource copying or fallback strings are
introduced. The one source line follows [validated Mobile source](https://github.com/fajarxfce/hris-mobile/commit/2eb833f460cf46fa2f1170bbb1656b5cd9144f27).

Independent Starter checks preserve all 1,052 prior test identities
(568 fresh and 484 exact unchanged). Root checks, formatting,
architecture, detekt, three Android variants, lint, production Web, app browser tests and Apple
source/test-source compilation pass. Both locale files match generated bytes inside all three
APK variants. The actual production APK was signed locally for the owned emulator, with every
unsigned ZIP entry unchanged. Its nondebuggable application cold-started and reopened in a new
process, remaining alive for both ten-second observations. Both screenshots were opened and
inspected. The emulator was stopped before any subsequent compilation.

Pinned Inspector 742a2d1c and its existing gradlew.bat difference remain unchanged. This port
contains no HRIS configuration or message policy. No physical phone installation or new Apple
runtime execution is claimed. Mobile release93 was independently delivered before this port.
